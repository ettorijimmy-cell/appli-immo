# Brand brief

Document volontairement léger : pour un usage mono-utilisateur, l'identité
de marque n'a pas besoin d'être poussée. Ce document sert surtout à garder
une cohérence visuelle pendant le développement, et servira de base si le
projet évolue vers une commercialisation.

## Nom du produit

À définir — champ ouvert, aucune décision prise à ce stade. Utiliser un nom
de code neutre dans le dépôt de code (ex. `gestion-locative`) en attendant.

## Positionnement

Un logiciel de gestion locative plus rapide et plus agréable à utiliser que
les outils existants du marché, pensé pour un propriétaire qui gère
plusieurs SCI et veut minimiser le temps passé en administratif — pas un
outil comptable complexe, un outil qui fait gagner des clics.

## Ton

Professionnel, sobre, direct. Pas ludique, pas familier — il s'agit de
gestion patrimoniale et de données de tiers (locataires). Les textes
d'interface doivent être clairs et concis, jamais approximatifs sur les
montants ou les dates.

## Palette de départ (ajustable)

Proposition de base pour rester cohérent avec la direction "sobre et
moderne" validée en Phase 6 UX. À valider ou ajuster librement — rien
n'est figé.

| Rôle | Couleur | Usage |
|---|---|---|
| Neutre | Slate (gris ardoise) | Fond, texte, structure |
| Accent | Indigo profond | Actions principales, éléments actifs |
| Succès | Vert | Paiement reçu, document valide |
| Alerte | Ambre | Échéance proche |
| Erreur | Rouge | Impayé, document expiré |

Mode sombre inclus dès le départ (Phase 6).

## Typographie

Police système sans-serif (coût de chargement nul, rendu natif cohérent
avec Windows) — pas de police custom à charger pour un outil desktop
professionnel où la vitesse de démarrage prime sur l'identité visuelle.

## À ne pas faire

- Pas de ton ludique ou d'emoji dans l'interface — incohérent avec le
  sérieux attendu d'un outil de gestion patrimoniale
- Pas de surcharge visuelle : le cahier des charges (Phase 6) demande la
  sobriété, pas la démonstration de fonctionnalités
